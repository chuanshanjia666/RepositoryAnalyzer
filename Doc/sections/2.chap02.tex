\chapter{代码静态/动态分析}
\label{chap02}

本章详细介绍针对代码库进行的深度质量分析。分析工作涵盖了代码复杂度评估、项目依赖安全审计、静态漏洞扫描以及动态测试覆盖率分析四个方面，旨在全方位评估软件的鲁棒性与可维护性。

\section{代码复杂度分析}

代码复杂度是衡量软件可维护性的重要指标。本项目利用了 \texttt{radon} 库，通过 \texttt{code\_analyzer.py} 模块实现了自动化的复杂度计算与可视化。

\subsection{分析方法与实现}
模块遍历仓库中的所有 Python 文件，基于抽象语法树 (AST) 计算以下核心指标：
\begin{itemize}
    \item \textbf{圈复杂度 (Cyclomatic Complexity, CC)}：通过计算代码中线性独立路径的数量来衡量逻辑复杂性。\texttt{radon.complexity.cc\_visit} 函数被用于解析代码块，统计控制流结构（如 if, while, for）。
    \item \textbf{可维护性指数 (Maintainability Index, MI)}：利用 \texttt{radon.metrics.mi\_visit} 计算的一个综合评分（0-100），该指标结合了圈复杂度、代码行数 (LOC)、Halstead 体积和注释比例。
\end{itemize}

\subsection{可视化分析}
分析结果被聚合后，工具生成了图 \ref{fig:radon_complexity} 所示的分布图。图中上部展示了有效文件的平均圈复杂度，下部展示了可维护性指数。这能帮助开发者快速定位那些复杂度过高（CC高）或难以维护（MI低）的“坏味道”模块。

\section{项目依赖与安全审计}

针对现代软件开发中普遍存在的“供应链安全”问题，\texttt{dependency\_analyzer.py} 模块基于 \texttt{pipdeptree} 和 \texttt{safety} 工具实现了深度的依赖分析。

\subsection{分析维度}
\begin{itemize}
    \item \textbf{依赖树解析}：通过调用 \texttt{pipdeptree --json} 命令，工具解析当前环境的依赖关系，构建出完整的依赖树。这不仅识别了直接依赖，还挖掘了隐蔽的传递依赖（Transitive Dependencies）。
    \item \textbf{漏洞数据库比对}：集成 \texttt{safety} 工具，将项目依赖版本与已知的 CVE 漏洞数据库进行比对，自动标记存在安全风险的包版本。
\end{itemize}

\subsection{结果展示}
图 \ref{fig:dependency_analysis} 展示了分析结果。左侧饼图反映了项目依赖的构成比例（直接依赖 vs 传递依赖），右侧直方图则统计了不同风险等级的漏洞数量。

\section{代码漏洞扫描 (SAST)}

为了在代码层面发现潜在的安全隐患，项目集成了 \texttt{bandit} 做为静态应用程序安全测试 (SAST) 工具。

\subsection{扫描机制}
\texttt{vulnerability\_scanner.py} 模块封装了 \texttt{BanditManager}。它不执行代码，而是将 Python 源码解析为 AST，并在节点上运行一系列插件来匹配已知的漏洞模式，例如：
\begin{itemize}
    \item 硬编码的敏感信息（密码、API Key）。
    \item 弱加密算法（如 MD5, SHA1）的使用。
    \item 危险的函数调用（如 \texttt{eval()}, \texttt{subprocess.Popen} 的 Shell 注入风险）。
    \item 不安全的网络绑定（如绑定到 0.0.0.0）。
\end{itemize}

\subsection{风险评估}
扫描结果被分类为 High, Medium, Low 三个风险等级。图 \ref{fig:vulnerability_viz} 直观展示了各类风险的分布情况，这为安全修复优先级提供了数据支持。

\section{代码质量与动态分析}

除了上述特定的分析外，工具还整合了 \texttt{pylint} 进行代码风格检查，以及 \texttt{pytest-cov} 进行动态测试覆盖率分析。

\begin{itemize}
    \item \textbf{Pylint 质量分布}：图 \ref{fig:pylint_viz} 展示了代码中各类问题的比例，包括规范（Convention）、重构（Refactor）、警告（Warning）和错误（Error）。
    \item \textbf{动态测试覆盖率}：\texttt{analyze.py} 模块尝试运行项目中的单元测试，并生成覆盖率报告 (`coverage\_report.txt`)，以评估测试用例对代码逻辑的覆盖程度。
\end{itemize}
